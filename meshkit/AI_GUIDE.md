# meshkit 作業ガイド（AI向け）

Blenderを使わずに、Pythonスクリプトでローポリモデルを作り、検査し、プレビュー画像で確かめ、OBJ / glTF に書き出すための手引きです。
MCPの `guide` ツールはこの文書を返します。

## 1. 作業の流れ

1. 寸法と座標系を決める（1単位＝1m、+X＝左、+Y＝上、+Z＝前）。
2. `build()` が `Model` を返すスクリプトを書く。
3. 実行する：MCPなら `run_script`、シェルなら `python -m meshkit run script.py`。
4. 返ってくる報告を読む。`ok` が true になるまで直す。
   - `issues`：穴、巻き順の不一致、裏返り、つぶれた面、平らでない面、凹の面
   - `floating`：どこにも接していないシェルの組（浮き部品）
   - `summary.size`：外形寸法。公表値と比べる
5. プレビュー画像を見る。おかしいところはモードや視点を変えて確かめる。
   - `mode=orientation`：裏面が赤く出る。穴や面の裏返りが一目でわかる
   - `mode=parts` と `wire=true`：パーツの分かれ方とポリゴンの割り方がわかる
   - `views=left,top,front`：正投影。図面と見比べられる
6. 開口（操縦席・窓など、テクスチャの不透明度0で開けた穴）やガラスのあるモデルは、透けの検査をする（8章）。
   - シェルなら `python -m meshkit run script.py --seethrough`、または `python -m meshkit seethrough model.obj --texture tex.png -o st.png`
   - MCPなら `run_script` の `seethrough=true`、または `seethrough` ツール
   - 報告の `open`（裏面が見える画素数）が0〜3になるまで直す
7. 数値を直して、3から繰り返す。形を手で直すのではなく、スクリプトを直す。

## 2. 座標系と単位

- メッシュキット内部は +X＝左、+Y＝上、+Z＝前、1単位＝1m（glTF、Minecraft/tudursvehiclemod と同じ）。
- Blenderで作られたOBJ（Z上）を読むときは `axes="blender"`（CLIでは `--axes blender`）を指定する。
- 原点の決め方は用途で決める。航空機は主輪の接地点、戦車は接地面の中心、艦艇は喫水線など。
- 可動部（砲塔・舵・脚など）は別パーツにし、`model.pivots[パーツ名] = (x, y, z)` に回転の中心を入れる。glTFではこれがノードの原点になる。

## 3. API

```python
import meshkit as mk
import numpy as np

def build():
    m = mk.Model("name")
    m.add("hull", mk.box(0, 0.5, 0, 2, 1, 4, tag="hull"))    # パーツ "hull" にシェルを追加
    m.pivots["$turret"] = (0, 1.0, 0)                          # 可動部の回転中心
    m.refs.append(("seat", (0, 1.2, 0), "seat"))               # 参照点（seat / muzzle / camera / 任意）
    return m
```

### 形状（どれも閉じた外向きのシェルを返す）

| 関数 | 用途 |
|---|---|
| `box(cx, cy, cz, sx, sy, sz, tag, M=None, pivot=None)` | 箱。`M` は回転行列（`rot_x/rot_y/rot_z/rot_axis`） |
| `cylinder(p0, p1, r0, r1=None, n=8, tag)` | 円柱・円錐台（任意の軸） |
| `lathe(p0, axis_dir, [(t, r), ...], n=8, tag)` | 回転体。r=0 の端は尖る（砲弾・スピナー・煙突） |
| `loft([ring, ring, ...], tag, tags=None)` | 断面の列をつなぐ。断面は同じ点数。1点の断面は尖端 |
| `ring_superellipse(cx, cy, z, hw, ht, hb=None, n=12, p=2.0)` | z一定の面上の断面（p=2楕円、p>2で角ばる）。胴体・船体・砲塔のロフト用 |
| `ring_on_axis(center, axis, radius, n)` | 任意軸まわりの円断面 |
| `prism(bottom, top, tag)` | 同じ点数の2つの多角形の間の立体 |
| `extrude_xz(poly, y0, y1)` | 平面図（x, z）の多角形を上下に押し出す（甲板構造物） |
| `extrude_zy(poly, x0, x1)` | 側面図（z, y）の多角形を左右に押し出す（車体側面・舵） |
| `extrude_xy(poly, z0, z1)` | 正面図（x, y）の多角形を前後に押し出す |
| `ellipsoid(center, rx, ry, rz, nu, nv)` | 楕円体 |
| `wing(stations)` / `fin(stations)` / `wing_section(...)` / `airfoil_2d(t, camber)` | 翼（NACA断面、ねじり、翼端の丸め） |
| `blade(root, tip, chord_root, chord_tip, thick, axis_spin)` | プロペラ羽根 |

シェルの操作：`.translate(x, y, z)`、`.rotate(M, pivot)`、`.apply(M, t, pivot)`、`.mirrored_x()`（左右反転コピー、巻き順も直す）、`.copy()`、`.retag(tag)`。

### テクスチャ

```python
from meshkit.texture import texture_model, value_noise
texture_model(m, (512, 512),
              colors={"hull": (100, 110, 70)},                 # 投影する面の地色
              flat={"track": (50, 50, 46), "gun": (60, 64, 52)},  # 単色の色見本に割り当てる小物
              paint=lambda atlas, model: atlas.paint3d(fn, tags=["hull"]))
```

- 面は法線の向きで上・下・側面・正面のどれかの投影図に割り当てられる。塗装は3D座標の関数で書く（`atlas.paint3d(fn(X, Y, Z, cur) -> (rgb, mask))`）。
- 左右で違う文字や番号を塗るときは `split_sides=True`。ガラスなど透ける面は `glass_tags` と `atlas.paint_alpha`。
- 開口（操縦席・窓）は `atlas.cut_alpha(fn, tags=, kinds=)` で、fn が真のテクセルを不透明度0にする（modでは穴になる）。開口の作り方の規則は8.2。
- `texture_model(..., fix_shared=True)`（既定）は、開口とテクセルを共有して誤って開く面・開かない面を見つけ（`atlas.hijacked()`）、専用の領域に移して（`atlas.solo`）アトラスを作り直す（8.3）。このため `paint` は複数回呼ばれることがある。渡された atlas だけから結果を作り、外の変数に積み上げない。
- 機体の下に吊るされた部品（フロート、脚カバー、脚扉など）の側面を下面色で塗るときは、`hanging_shells(model, tags=...)` で部品を探し、`atlas.face_mask(shells, kinds=("side", "front"))` で塗る範囲を選ぶ（8.5）。
- 実行すると `model.uvs` と `model.texture` が入る。色分けだけでよければ `flat="all"`。

### 検査・表示・入出力

```python
from meshkit import check, view
rep = check.report(m)                          # ok / issues / floating / summary
view.sheet(m, views=("iso", "left", "top"), mode="orientation", wire=True).save("p.png")
view.render_view(m, {"eye": (8, 4, 8), "target": (0, 1, 0), "fov": 30})  # 任意のカメラ
check.clearance(m, "$propeller", m.pivots["$propeller"], (0, 0, 1),   # 回す部品が他に当たらないか
                tags=("prop",))                                     # （羽根だけ・1周）
mk.save(m, "out.obj"); mk.save(m, "out.glb")
m2 = mk.load("other.glb")                      # OBJ / GLB / glTF を Model として読む

from meshkit import seethrough                 # 透けの検査（8.4）
st = seethrough.check(m)                       # open / glass（画素数）、where（部品と位置）
seethrough.sheet(m, st).save("st.png")         # 最も悪い視点。裏面＝マゼンタ、ガラス越し＝シアン
```

- 視点：`iso`、`iso_rear`、`iso_below`、`iso_left`、`iso_right`（透視）、`front`、`back`、`left`、`right`、`top`、`bottom`（正投影、自動で収める）。
- `left` は +X 側（モデルの左舷）から見た図で、機首が画像の左に来る。`top` は機首が上。
- 参照点（`model.refs`）の印は隠れていても手前に描かれる（seat＝黄、muzzle＝赤、camera＝水色）。
- 回転・折りたたみ・旋回する部品は `check.clearance(model, part, pivot, axis, angles, tags, ignore)` で、動かしたときに他の部品へ当たらないかを確かめる（例：プロペラの羽根を1周、折りたたみ翼を0〜110度）。
- 引き込む部品（脚・車輪）は `attach.outside(model, transforms, parts, skip_tags=("door",), samples=3)` で、引き込んだ姿勢で機体の外にはみ出していないかを確かめる（外に出ている表面点の割合。0が目標。`samples` は三角形の面上の点も調べる細かさで、頂点の間で外板を突き抜けるのも見つかる）。脚扉のように外板に沿わせる部品はタグで除く。
- 浮いた部品の検出は `attach.groups(model, transforms)`（つながったシェルのまとまり。2つ以上なら浮きがある）。
- 姿勢を変えて見る：`view.render_view(m, "iso", transforms={"$gear_l": fn})`。fn は点の配列を受け取って返す関数。

## 4. 守ること

- 各シェルは閉じたメッシュにする。どの辺もちょうど2面が逆向きに共有する。開いた形が欲しいときも、薄い板（厚み数mm〜数cm）にする。
- 部品は少し食い込ませてつなぐ（数cm）。同じパーツの2つのシェルで頂点の位置を完全に一致させない。
- 多角形の面は平らで凸にする。凹の断面は三角形に分けるか、`loft` の端に任せる（凹なら自動で扇状に分割される）。
- 背面カリング（裏面を描かない）で表示される前提で作る。`mode=orientation` で赤い部分が出たら、穴か裏返り。
- ガラスの内側には内装（床・座席・計器盤など）を入れる。外板の裏は描かれないので、空洞に見える。
- 開口の縁からのぞける範囲には、表を向けた面（くぼみの壁・床、内張り、隔壁）を必ず置く。外板の帯や隙間が残ると、その裏面＝空が見える（8.2）。
- 開口やガラスのあるモデルは、`seethrough` の `open` を0〜3画素にする（8.4）。
- 三角形数を報告で確かめる（目安：戦闘機・戦車は約1,000、大型機は2,000以下、艦艇は10,000以下）。


## 6. 現代兵器用キット（0.3.0）

現代パック（ジェット機・主力戦車・現代艦艇42種）の制作で、WW2機向けの手法では形が実物から外れる点がいくつも見つかりました。
その対策をモジュールにまとめたものです。例は `examples/modern/` の4本（単発戦闘機・双発戦闘機・西側主力戦車・イージス駆逐艦）です。

### 6.1 モジュール一覧

| モジュール | 主な関数 | 用途 |

| `meshkit.planform` | `from_published(面積, 翼幅, 前縁後退角, テーパ比, z_le_root, y, dihedral, x_root)`、`trapezoid(半翼幅, 翼根弦, 翼端弦, 後退角, ...)`、`surface(half)`、`fin(root, tip, x, cant, mirror_x)`、`plate(outline)`、`split(half, x)`、`station_at`、`describe(half)` | 直線の台形翼・尾翼・カナード・垂直尾翼・ストレーキ。翼端は丸めず切り落とす |
| `meshkit.fuselage` | `body`、`pod`、`canopy`、`body_with_tub(stations, tubs)`、`cockpit_fittings`、`cover_nozzles(stations, nozzles)`、`nozzle`、`intake_face`、`rider_feet_y` | 胴体・ナセル・テールブーム、コックピットのくぼみ、ノズルを内包する後部胴体 |

### 6.2 ジェット機

- **翼は直線の台形にする。** 前縁・後縁は直線、翼端は切り落とし（`planform.surface`）。`geom.wing` の既定（`round_tip=True`）はレシプロ機向け。
- **翼弦は推定せず公表値から出す。** 翼面積・翼幅・前縁後退角・テーパ比から `from_published` で作り、`describe` で面積・後退角を確かめる。
- **途中の折れは実機にある時だけ。** F-4 や A-10 の外翼のように実機に折れがある場合だけ `trapezoid(..., crank=(x, 後退角, 上反角))` を使う。
- **胴体幅の広い機体・ブーム付きの尾翼は左右別パネル。** ステーションを x > 0 から始めると、`surface` が左右2枚にする。
- **双発機の後部胴体はノズル2基を内包する幅にする。** `cover_nozzles` が後部ステーションを自動で広げる。そのうえで `check.penetration(m, ["tail"], ["fuselage"], tags_b=("nozzle", "exhaust"))` が0であることを確かめる（尾翼がノズルを貫通していない）。
- **国籍標識は平らな面に置く。** `check.marking_spot` で、標識の円が面からはみ出さないか（coverage が1）、段差をまたがないか（relief が小さい）を確かめる。主翼が胴体の最後部まで付いていない機体（デルタ翼など）は特に注意。
- **コックピット**
  - `body_with_tub` でキャノピーの下にくぼみを作り、`cockpit_fittings` でシートと計器盤を置く。
  - 乗員の足元を座席位置に置くエンジンでは、`rider_feet_y(floor)` で腰がシートに乗る高さを出す。tudursvehiclemod は0.7倍の縮尺で描くため、腰は足元から約0.49 m上になる。
- **引き込み脚**
  - `gear.stow` で角度（前脚は前後どちらに畳むかも含む）と、畳んだ後の平行移動を探索する。
  - 残りは `fairings` で左右対称の膨らみを付け、はみ出しを **0%** にする。
  - 「回転してから自分の座標で平行移動」するエンジン（tudursvehiclemod の `slide_rotate`）には `Retraction.rotate_then_slide_offset()` を渡す。

### 6.3 主力戦車

- **車体前面は角度から作る。** `armor.glacis(z_nose, nose_y, roof_y, upper_deg, lower_deg, ...)` を使う。
  - 西側の第3世代：上部前面は水平から約8〜12度（長く緩い）、下部前面は約35〜45度（短く急）。
  - ソ連・ロシア系：上部前面は約22〜30度。
- **西側戦車の車体上面は平らではない。** 緩い前面 → 砲塔リング付近の平坦部 → 機関室で一段上がり後方へ緩く上る（`hull(..., rear_deck=(z_front, z_rear, y_front, y_rear))`）。砲塔の張り出しは `faceted_turret(..., bustle=(z_split, 底上げ量))` で底を上げ、旋回しても機関室に当たらないようにする。
- **車体上部を絞るのは T-54/55 世代だけ。** `hull(..., upper_w=..., fender_y=...)` で履帯の上にフェンダーを付ける。T-72/80/90 と M60 は全幅。
- **差別化は砲塔形状とモジュールで行う。** 鋳造砲塔は `cast_turret` で、前半分の指数 p_front < 2 にすると尖った機首（M60）になる。溶接砲塔は `faceted_turret` で作る。
- **全幅は公表値に合わせる。** 楔形の前面装甲は砲塔の外形そのものに組み込み、外へ張り出す板を足さない（10式で全幅が3.6 mになった失敗）。`check.compare_size` で確かめる。
- **モジュールは面に接して置く。** `turret_half_width(turret, z, 高さの割合)` で砲塔側面の位置を求めて置くと、浮きも外への張り出しも出ない。
- **履帯**
  - `track_path` で経路を作り、`link_spacing` でコマの間隔を出す。
  - エンジンが履帯を描く場合でも、プレビューと接触確認には `lay_links` でコマを並べる。

### 6.4 現代艦艇

- **個性は上部構造で出る。** `house` は傾斜壁の多角形デッキハウス。上面を広くすれば窓が外へ傾いた艦橋になる（`bridge`）。
- **レーダーのアレイ面は壁に沿わせる。** `wall_point` で傾斜壁上の位置を出し、`array_face` を壁の法線方向に向けて置く。
- **三角形の配分**
  - 喫水線より下は、ビルジとキールの点だけで十分（`hull`）。三角形は水線より上に使う。
  - 目安：駆逐艦・巡洋艦は5,000〜7,000、戦艦・空母は5,000〜10,000。
- **艦番号は左右どちらからも読めるようにする。** `texture_model(..., split_sides=True)` と `detail.side_number` を使う。
- **小物は必ず何かに接する。** 艇は甲板や構造物の上に載せ、ヤードはマストと同じ前後幅（`yard(..., depth=)`）にする。手すり・ボラードは `deck_at` で甲板の高さに合わせる。

### 6.5 テクスチャの書き込み

- **順番**：地色・迷彩 → `tone` → パネルライン・リベット・点検パネル（航空機）／外板の継ぎ目・VLSのふた（艦）／転輪のハブ・グリル（戦車） → 標識・番号 → `ink` → `grime`・`streaks`・`chips`・`soot`。
- **`ink`（墨入れ）**：投影面ごとに、面の種類・奥行きの段差・傾きの折れを検出して線とぼかしを入れる。ローポリの箱でも形が読めるようになる。
- **解像度の目安**：航空機・戦車は1024px、艦艇は2048px。
- **注意**：点検パネルや扉は規則的に散らした推定なので、実物の配置を再現したい部分は `rect_fn` で個別に描く。

## 7. ロボット（メカ）用キット（0.4.0）

Mech Frame（tudursvehiclemod のロボットアドオン。標準機9機、変形セット3種、拡張パック4社42パーツ）の制作で得た手法をまとめたものです。
形状の関数は `meshkit.mech`、例は `examples/mech/concept_legs.py`（同じ関節位置の脚を4つのデザイン言語で作り分け、数値を比べる）です。

### 7.1 モジュール（`meshkit.mech`）

| 関数 | 用途 |
|---|---|
| `stack` / `seg` / `cbox` / `cyl` / `mirror` / `nozzle` | 面取り矩形の積み上げ・折れ線ロフト、面取り箱、軸、左右反転、ノズル |
| `pent2d` / `pstack` / `pseg` / `zloft` | 前を向く丸い五角形の断面（軽量機の言語）。正面は細く、側面は長く尖る |
| `plate` / `slab` / `hbox` | ボルト留めの装甲板、凸多角形の板、強く面取りした塊（重装甲の言語） |
| `tube` / `truss` | むき出しの管と格子桁。`truss(..., n=4)` で角材にすると三角形が1/3 |
| `beam` / `girder` / `at` / `panel` / `claw` | 骨抜き機の言語：角材（`beam`）、斜材付きの三角断面の桁（`girder`）、支柱で浮かせた別体の装甲板（`panel`。支柱が板に届かないと例外）、6三角形の爪・棘（`claw`） |
| `chine_seg` / `chine_stack` / `split_warped` | 鋭い稜線を持つ六角形断面（ステルスの多面体言語）。形の変わるロフトのねじれた四角形は自動で三角形に分ける |
| `cast` / `cast_seg` | 超楕円断面（p≒2.6）の鋳造装甲の塊（要塞の言語） |
| `R3` / `axis_angle` / `align` / `frame_rot` / `M4` / `quat` / `slerp` | 関節の回転（変形の姿勢づくり） |
| `volume` / `fill_ratio` / `proportions` / `limb_report` | コンセプトの数値化（充填率、正面幅/側面奥行き）と脚の寸法・休止時の曲がり |

### 7.2 部品の作り方

- **動く単位ごとにパーツ（グループ）を分ける。** 骨盤、腿、すね、足、肩、上腕、前腕、頭。回転の中心（関節）を決めてから形を作る。
- **関節は両側の部品に食い込む軸（円柱）で作る。** 軸は子の側に入れる（膝の軸はすねのグループ）。親の端は軸の外周に数cm食い込ませる。脚の部品が離れて見える原因の多くは、ここが「接しているだけ」になっていること。
- **脚は股・膝・足首の点で決める。** 膝には休止状態で20〜40度の曲がりを付け、曲がる向き（pole）を決める。真っ直ぐだとIKが曲げる向きを決められない（`limb_report` の `bends` で確かめる）。
- **腿：すね≒1：1**（逆関節は短い腿・短い中間節・長いすね）。腿を長くすると、深く曲げたときに膝や第2関節が腿にめり込む。
- 左右対称の部品は左を作って `mirror` する。可動部の名前は左右で `l_` / `r_` をそろえる。

### 7.3 コンセプトからデザインへ

コンセプトを1文で決め、それを「断面」「関節の扱い」「塊の置き方」「色の役割」の4つの規則に落とします。規則が決まれば、どの部品もその会社の物に見えます。

| 言語 | コンセプト | 断面 | 関節 | 塊・シルエット | 充填率の目安 |
|---|---|---|---|---|---|
| 軽量 | 速さのために細く | 前を向く丸い五角形 | 細い首・腰・足首、肩・肘・膝だけ太く | 正面は細く側面は深い（正面幅/側面奥行き < 0.8） | 0.3前後 |
| 骨抜き（超軽量） | 飛ばない物はすべて重り | 斜材で三角形に組んだ角材の桁。装甲は別体の尖った薄板を支柱で浮かせて並べる。操縦席と感覚器だけ卵形の殻 | 円盤だけの軸、アクチュエーター（ラム・ばね）を見せる | 背が高く細い、板の先端が上・前・後ろに尖る、過大なスラスター | 0.05〜0.1 |
| ステルス | 最後に見つかる | 稜線のある六角形、平面だけ | 六角形の軸、くぼんだスリット | 直線だけの輪郭、縁の角度をそろえる、鋸歯の縁 | 0.3前後 |
| 要塞（超重量） | 歩く城 | 鋳造の超楕円 | 何重ものスカート板と膝当てで覆う | 肩が脚より広い、頭は肩より低く埋まる | 0.45以上 |

- **骨抜きでも、自重を支えられる構造に見せる。** 細い管を1本つないだだけの手足は「歩くだけで折れそう」に見える（指摘を受けた点）。部材は角材にして弦材を2〜3本並べ、斜材で三角形に組む（`girder`）。胴は輪と縦通材の箱に、側面へX字の筋交いを入れる。
- **骨抜き機の装甲は「骨組みに沿って浮かせた別体の板」。** 板は骨組みの面と平行に、面から 0.1 m ほど離して支柱で留め、板どうしも 0.05〜0.1 m 空ける（関節や肩の張り出しの所で分割する）。隙間から骨組みが見えるのが軽さの表現。板は覆うためでなく空気を受け流すために置く：進行方向（+Z）に対して斜めか水平にし、正面を向く板は作らない。胴の前は骨組みの縦材を1点に集めた円錐の機首にして、その面ごとに板を張る。手足の板は外側面に縦に並べ、膝は脚の面内のひれにする。板の外形は尖った五角形で、先端を上・前・後ろへ向けて鋭いシルエットにする。
- **重量級ほど関節を太く・隠す。軽量級ほど関節を細く・見せる。** 同じ骨組みでも、関節の扱いだけで重さの印象が変わる。
- **色は7つの役割で塗る**：armor（地）、armor2（第2色）、frame（関節・内部）、accent（差し色）、eye（発光）、nozzle、metal（＋glass）。会社ごとにこの組を1つ決め、差し色は「アクチュエーター」「縁」「先端」など置く場所の規則も決める。暗い配色は面の陰影が見えにくいので、armor と armor2 の明度差を大きめに取る。
- **変形機は同じ会社の通常機の部品関数を使い回し**、翼パックや機首など変形に必要な物だけ足す。系統が一目で分かり、作業も減る。

### 7.4 脚の種類別

- **二脚**：股の高さ 2.9〜3.3 m。足は前に長い五角形（または六角形）の塊で、つま先は足首より 0.6〜0.9 m 前。
- **逆関節**：横から見て稲妻形。短い腿が前下へ、短い中間節が後上へ（第2関節は膝より高い）、長いすねが前下へ。
- **多脚**：胴の縁に付け根の回転ブロック（coxa、縦軸）、腿は外上へ上がって胴より高い膝、すねは外下へ。関節は上と前から板（フェンダー）で守る。四脚は対角、六脚は三脚ずつの組で歩くので、隣の脚と前後の可動範囲が重ならない間隔にする。
- **タンク**：車体はどの重量級でも閉じた水密の箱（船形）にする。骨抜き機でも格子だけの車体にはしない。履帯は台形（短い接地面、前の誘導輪へ上がる斜面、高い起動輪、長い上部）。転輪は回転グループ（中心と半径）。スカートで上部を隠し、転輪は下から見せる。
- **ホバー**：脚なし。スカートは接地面から 0.3〜0.5 m 浮かせ、下面に発光、周囲にファンのダクト。

### 7.5 変形

- **ジェット形態の配置は手で打たない。** 各グループを親に関節でぶら下げ、ロボット形態の配置を関節まわりに回したものを使う（Mech Frame の `rig.Rig`）。こうすると両形態でも変形の途中でも、関節が外れない。
- **確かめるのは t=0.25 / 0.5 / 0.75 / 1.0 の4コマすべての浮き部品**。最終形だけ見ても途中の外れは分からない。
- よく使った形：
  - コアの寝かせ方：`R3(rx=-90, ry=180)`（頭が前・胸が上）、`R3(rx=-90)`（頭が後ろ・胸が上）、`R3(rx=90)`（頭が前・胸が下）。
  - 脚：まっすぐ後ろへ伸ばして閉じる（股を内へずらす `slide`）＝尾部や機首。すねを前へ折り返す（Z折り）＝全長を詰める。すねを軸まわりに転がすと、ふくらはぎのフィンがV尾翼や水平尾翼になる。
  - 翼：背中に垂らして畳み、関節で横へ振り出す（`frame_rot` で翼幅・翼弦・面の向きを一度に決める）。外側の板は内側に重ねて畳み、ヒンジで180度開く。ヒンジが翼弦方向なら翼幅が倍、翼幅方向なら翼弦が倍になる。
- 噴射口・当たり判定の高さは、リグで変換した点から計算して書き出す（手で測らない）。

### 7.6 三角形の予算

- 目安は**武器込みで1機5,000以下**。武器が4つで約900使うので、脚1,400〜1,800、コア700〜1,000、腕600〜1,000、頭200〜350、ブースター500〜650。
- 多面体（六角形断面）は安く、管と格子は高い。格子は角材（n=4）、管は継ぎ目のリングを省く（`tube(..., joint=0)`）、リングは4面の角柱を並べる、小さな発光窓は板1枚にする。

### 7.7 動きを見越した形

歩行の調整で分かった、形の側で決めておくべきこと。

- **足の前後の幅は歩幅の半分以下に。** 大きな足は踏み出しで隣の足や反対の脚に当たる。
- **多脚は脚ごとに前後の「通り道」を持てる間隔で付け根を並べる。** 付け根の間隔が狭いと、どんな歩き方でも隣どうしが重なる。
- **膝の休止時の曲がりが、着地の沈み込みとジャンプの伸びの余裕になる。** 伸び切った脚は着地を吸収できない。
- 二脚は脚の外側に揺れる物（スカート、フィン）を付けすぎない。横移動のとき脚が外へ開く。

### 7.8 検査

- 部品ごとに `check.report`（穴・裏返り・凹の面）、組み上げた機体でグループ単位の浮き部品、変形機は途中の4コマ。
- プレビューは `mode=tags` で会社の配色を当てて、斜め・横・正面・上の4方向。シルエットは横と正面で判断する。
- `proportions` / `fill_ratio` で会社ごとの数値がそろっているか見る。骨抜き機に塊が混ざると充填率が跳ね上がる。

## 8. 透け（裏面の露出）と塗り分け（0.5.0）

vehicleaddonww2 の航空機59機の修正（2026-10）で分かったことをまとめた章です。
きっかけは、零戦52丙型の主翼付け根で胴体との接続部から面の裏側（＝空）が見えていたことでした。全機を検査すると、同じ型の欠陥が多くの機体にありました。
あわせて、機体の下に付く部品の側面が上面色になっていた塗り分けの不備も直しました。

### 8.1 裏面が見える仕組みと原因の型

- mod は面を表側からしか描かず（背面カリング）、不透明度0のテクセルは穴として何も描かない。
- 視線が穴（開口・隙間・抜けた面）を通り、その先で面の裏に当たると、何も描かれず背景が見える。外から見て閉じているモデルでも、開口から中をのぞくと起きる。
- 見つかった原因は次の7つの型に分かれた。

| 型 | 例（vehicleaddonww2） | 対策 |
|---|---|---|
| テクセル共有で、隠れた面まで開く | 主翼付け根の上面が操縦席の開口とテクセルを共有し、主翼後縁の隙間から透ける（52型・52丙型・Fw 190A-8・Yak-3）。乗員区画の床が窓と共有して開く（B-25J・B-29 の尾部銃座） | `fix_shared`（8.3） |
| テクセル共有で、開くべき面が開かない | 操縦席の肩の外板が翼端とテクセルを共有して帯状に残り、操縦席越しにその裏が見える（Ju 87） | `fix_shared`（8.3） |
| 開口の縁と壁の間に外板の帯が残る | 開口を壁の内側までしか切らず、縁と壁の間に外板が残る。操縦席の反対側からその裏が見える（E7K2・KOR-1・Po-2、キャノピー越しの多くの機体） | 開口を壁の上端まで切る（8.2） |
| 開口が前後を向いた面まで切る | 操縦席の後ろの背（亀甲）の前面が開く（FM-2） | `kinds=("top", "side")` だけ切る（8.2） |
| 内張りと外板の間の隙間 | 6角形の内張りと丸い外板の間が広く、窓越しに外板の裏が見える | 内張りは胴体と同じ断面を内側へずらす（8.2） |
| 内張りの端の処理 | 内張りが尾端で胴体の外へ突き出る。先端の円錐部が空洞のまま見える（B-25J の尾部） | 円錐部まで延ばして細く追従させる（8.2） |
| 窓の範囲が広すぎる | 胴体窓の判定が主翼付け根のフィレットまで含み、そこがガラスになる（B-25J） | 窓はその窓がある面だけに限る（8.2） |

### 8.2 開口の作り方

- **テクスチャで穴を開けただけでは開口にならない。** 外板には厚みも壁もないので、縁を斜めにのぞくと反対側の外板の裏が見える。開口の縁からのぞける範囲には、表を向けた面（くぼみ＝tub の壁と床、内張り、隔壁）を必ず置く。
- **開口は壁の上端の上まで切る。**
  - 壁の上端は外板から15〜20 mm出しておき、切り抜きはその上まで広げる。開口の縁と壁の間に外板を1テクセルも残さない。
  - 判定は「テクセル全体が壁の上か内側にある」ときだけ切る（半テクセル＋5 mm の余裕）。テクセルの階段で縁が壁の外へはみ出さない。
- **切るのは上向きと横向きの面だけ**（`cut_alpha(..., kinds=("top", "side"))`）。前後を向いた面（風防の整形、操縦席の後ろの背の前面）は開口に含めない。
- **壁の上端は外板に沿わせる。** 細くなる開口を曲面のキャノピーの下に作ると、断面と断面の間を直線でつないだ壁の上端が外板の下にもぐる。もぐる区間には断面を足す（Walrus で発生）。
- **内張り**（爆撃機の機首・胴体・尾部の乗員区画の筒）
  - 断面は胴体と同じ多角形（同じ角数・同じ角度）を内側へずらしたものにする。角数の少ない筒は外板の角の下に隙間を作る。
  - ずらし量は断面が小さい所で制限する（例：外側 min(余白, 0.15r)、内側はさらに min(厚み, 0.1r)。r は断面の幅・高さの半分のうち最小のもの）。先端の円錐部では断面に合わせて細くなる。
  - 開いた端（隔壁のない端）が機首・尾部の先端から0.6 m以内なら、先端まで延ばす。ガラスが円錐全体にある場合、円錐の中が見えてしまう。
  - 窓の判定は、内張り上の点ではなく、そこから外へ向かった外板上の点で行う。さらに縁から（余白＋厚み＋1 cm、既定で8 cm）内側に寄せる。開口の縁を通る視線が、内張りと外板の隙間に届かない。
- **窓の範囲は、その窓がある面だけに限る**（例：胴体側面の窓は |X| < 1.0 として、主翼付け根のフィレットを除く）。判定関数は3D座標の関数なので、範囲を広く書くと別の部品まで透明になる。

### 8.3 テクセルの共有と `fix_shared`

- 投影アトラスでは、ある投影図で別の面の後ろに隠れる面は、手前の面のテクセルを共有する（`assign_layers` が別の層に分けるのは、面の多くが隠れる場合だけ）。色は手前と同じでよいので、テクセル密度を保てる。
- ところが `cut_alpha` の判定は、テクセルの持ち主の面の位置で行われる。そのため隠れた面は、開いてはいけない所が開いたり（主翼付け根の上面、区画の床）、開くべき所が開かなかったり（操縦席の肩の外板）する。
- `texture_model(fix_shared=True)`（既定）の処理：
  1. paint のあとに `atlas.hijacked()` が、面ごとに次の2つを比べる。食い違う面を集める。
     - その面の平面上の点での切り抜き判定
     - 共有しているテクセルの状態（別の面のテクセルで、面の平面から `tol` 以上離れているもの）
  2. 集めた面を `atlas.solo` に登録し、専用の領域（`top#solo#<パーツ>#<シェル>` など）に移してアトラスを作り直す（最大3回）。
- 代償は、専用の領域の分だけテクセル密度が下がること（航空機で最大約7%）。
- `texture_model` を使わずに `Atlas` を直接組み立てる場合は、`hijacked()` が空になるまで繰り返す。

```python
solo = {}
for _ in range(4):
    at = build_atlas(model, solo)       # Atlas(...); at.solo = dict(solo); collect / layout / rasterize / 塗装 / cut_alpha
    hj = at.hijacked()
    if not hj:
        break
    solo.update(hj)
```

- `atlas.fmap` はテクセルごとの持ち主の面（`atlas.faces` の番号、-1＝なし）です。`atlas.face_mask(shells)` は、指定したシェルの面が持つテクセルを選びます。

### 8.4 透けの検査（`seethrough`）

- **方法**：モデルの周り32方向から、遠く（中心から外接球の半径の2.3倍、画角40度）と近く（半径の1.1倍、画角50度。開口の中をのぞく）の計64視点で描く。1回の走査で4つの深度バッファを作る。
  - **open**：表の面だけ描く（不透明度＞0）と何も当たらないのに、両面を描くと何かに当たる画素。面の裏が見えている＝欠陥。
  - **glass**：ガラス（不透明度250未満）も穴として扱った同じ判定。ガラスを持つパーツ自身の裏は数えない（1枚板のキャノピーの内側から枠が見えないのは許容）。
  - 視線上のすべての面が穴なら（横から見た開放式の操縦席の向こうの空）、欠陥にしない。
- **目標**：open は0〜3画素（シルエットの縁をかすめる1画素は誤差）。glass は数十画素まで。
- **読み方**：
  - `where` の `part`（裏が見えている部品）と `med`（その中央の位置、モデル座標）で場所を特定する。
  - 画像（`-o`）で、裏が見える画素をマゼンタ、ガラス越しをシアンで確かめる。数画素しかない時は丸で囲まれる。
  - 位置と部品から 8.1 の型を当てる。テクセル共有なら `fix_shared` が効いているか（`atlas.solo`）、帯なら開口と壁の位置関係を見る。
- **除外**：エンジンが描く部品（履帯など）は `skip` で外す。
- **時間**：1体10〜30秒（360画素・64視点）。
- **結果の例**（vehicleaddonww2 の航空機59機）：
  - 修正前は、裏の見える画素が数百〜数千の機体が多数あった。修正後は42機が3画素未満になった。
  - 残ったのは、ハッチの縁をかすめて外板と内張りの隙間（約5 cm）に届く視線（Sunderland・H8K2 で数十画素）と、テクセルが粗い機体の開口の縁（Ju 87）で、許容とした。塞ぐなら、開口の縁に外板と内張りをつなぐ枠を入れる。

### 8.5 上面色と下面色の塗り分け

- 胴体の塗り分け線（側面の高さ）だけで塗ると、機体の下に付く部品の側面が上面色になる。対象は、フロートとその支柱、翼端フロート、脚カバー（スパッツ）、脚扉、翼下のラジエーター、尾翼の支柱など。
- これらは下や横から、海や空を背にして見られる。史実で上面色と確かめられた場合を除き、側面も下面色にする。
- `hanging_shells(model, tags=("body", "cowl"))` が対象の部品を探す。
  - **機体（core）**：胴体（または船体）の最大のシェルと、主翼・尾翼・折りたたみ翼（`$wing_fold*`）の大きなシェル（その部品の最大の30%以上）。
  - **判定**：上を向いていない面の60%以上（面積）で、真上に機体があり、真下にはない。または、胴体の最下点より下にある。主翼と、その下の胴体の間にある支柱やナセルは対象にならない。
  - **対象外**：塗装色のタグ（`tags`）の面が半分未満のシェル（単色の小物）。フラップなど主翼の一部は、タグを分けて外す。
- 塗り方は、迷彩を塗った後に、側面と正面の投影だけを下面色にする。上を向いた面（top の投影）は上面色のまま。

```python
from meshkit.texture import hanging_shells
def paint(atlas, model):
    ...                                                   # 地色・塗り分け線・迷彩
    hang = hanging_shells(model, tags=("body", "cowl"), skip=("float_strut_l",))   # skip: 史実で上面色の部品
    atlas.img[atlas.face_mask(hang, tags=["body", "cowl"], kinds=("side", "front"))] = lower_rgb
```

- **史実の確認**：除外するのは写真や資料で確かめた部品だけにする。例として、Ju 87 の脚カバーには上面迷彩色の資料がある（パックでは下面色のまま、変更していない）。
- vehicleaddonww2 では17機の色が変わった（Be-4、KOR-1、Walrus、H8K2、PBY-5A、BV 138、MS.406、Mörkö-Morane、Yak-3、Spitfire IX、B6N2、Il-2、Ju 87C/D/G、Bf 109T、Sunderland）。ww2gen では `scheme['lower_parts']=False` で無効、`scheme['lower_parts_skip']` で部品を除外できる。

### 8.6 作業の手順

1. 開口は 8.2 の規則で作る（壁・床・内張りを先に置き、開口は壁の上端まで、上向きと横向きの面だけ切る）。
2. `texture_model` は `fix_shared=True`（既定）のまま使う。`atlas.solo` に入った面の数を記録しておくと、変化に気づける。
3. `seethrough` で open が0〜3画素になるまで直す。open が出たら、`where` と画像から 8.1 の型を当てる。
4. 1機で見つかった型は、同じ作り方をした全機で検査する（同じ型が別の機体にも出ている）。
5. 塗り分けは、下からの斜め視点（`iso_below`、左右）で、吊るされた部品の側面の色を確かめる。

## 9. 建設機械（重機）用キット（0.6.0）

tudursvehiclemod の重機アドオン（Construction Machinery Addon のサンプル機と、Meshkit で作った Construction Detail Pack：バックホウ2機、ラフテレーンクレーン、ブルドーザー、打撃式・回転貫入式・大型三点支持式の杭打機、ダンプ、ミキサー車、トラクターとトレーラー）の制作と修正（2026-10）で分かったことをまとめた章です。
形状と検査の関数は `meshkit.machinery`、例は `examples/machinery/crawler_rig.py`（履帯・旋回体・1本シリンダーで起伏するマスト・アウトリガー・振れ止め、姿勢の検査まで）です。

重機は「動く部品の組み合わせ」が本体です。形の良し悪しより、**どの姿勢でも部品が外れず・重ならず・構造として成り立つこと**で評価されます。指摘の多くは、静止した1姿勢だけを見て作ったことが原因でした。

### 9.1 モジュール（`meshkit.machinery`）

| 関数 | 用途 |
|---|---|
| `crawler_layout` / `layout_overlaps` | 履帯の配置（誘導輪・起動輪・転輪・上部転輪・経路）を重ならないように決め、重なりを数える |
| `crawler` | 片側の履帯一式（フレーム、ヨーク、歯付きの起動輪、誘導輪、転輪と軸・ブラケット、上部転輪、履板）。履板は1枚（エンジンが並べる）・経路に並べる（プレビュー）・1枚ずつ別パーツ（アドオンが動かす）を選べる |
| `path_length` / `link_spacing` / `place_on_path` / `link_shells` | 履帯経路の長さ、割り切れる履板の間隔、経路上の位置と向き、履板の形 |
| `ram_lengths` / `ram_stages` / `ram_leverage` / `ram_mount_search` | 油圧シリンダーの最短・最長、必要な段数、てこの長さ（ヒンジからシリンダーの線までの距離）、取付位置の探索 |
| `ram` / `ram_joints` | シリンダーの形（筒とロッド、または多段）と、どの姿勢でも両端のピンから外れない関節（`aim`＋`reach`） |
| `corner_mounts` / `outriggers` | 四隅から斜めに張り出すアウトリガー。張り出し→接地を1チャンネルで |
| `clamp_jaws` | 中央が空洞の半割リング2つ（杭打機の振れ止め、クランプ）。左右に開く |
| `joint` / `point` / `solve` / `pose_transforms` / `posed` | 関節の定義（Construction Machinery Addon の書式）、姿勢の計算、プレビュー用の変換、姿勢を付けた複製 |
| `sweep_poses` / `sweep_check` / `ram_drift` | 姿勢の総当たり、各姿勢での浮き部品・めり込み、シリンダーの先端と取付点のずれ |

関節は Construction Machinery Addon と同じ書式の辞書です（モード：`rotate` `slide` `scale` `aim` `reach` `belt`）。モデルを作るスクリプトから関節も出力し、同じ関節で検査すれば、ゲームで動くものをそのまま検査できます。`solve` は Detail Pack のプレビュー用ソルバー（アドオンの JointSolver の移植）と同じ結果になることを確かめてあります。

### 9.2 作業の流れ

1. **動く単位と回転中心を先に決める。** 旋回体、ブーム・アーム・バケット、リーダー、ヘッド、履帯のフレーム、アウトリガーの梁と脚。チャンネル（`swing` `mast` `outrigger` など）と、その 0〜1 で何度・何m動くかを決める。
2. 部品は「親に付いて一緒に動く物」を親子にする。旋回に追随する物（アウトリガー、運転席、シリンダーの根元）は旋回体の子。
3. 形を作り、同じスクリプトで関節を出力する。
4. `sweep_poses` で姿勢を総当たりし、`sweep_check`（浮き・めり込み）と `ram_drift`（シリンダーの外れ）を0にする。
5. 横・斜め・下から、起立／途中／格納の3姿勢をプレビューで見る（`pose_transforms` を `view.render_view(..., transforms=)` に渡す）。
6. ゲーム側の動作（チャンネルを動かすmodの処理）が絡む物は、ゲーム内のテストでも確かめる（例：振れ止めが開く高さ）。

### 9.3 履帯（クローラー）

戦車の足回りと同じ規則で配置します（`crawler_layout`）。

- **誘導輪（前）と起動輪（後）** は、上面が履帯の上側の内側に接する高さ。半径は同じでよい。
- **転輪は下側の走行面に並べ、誘導輪・起動輪からも互いからも隙間（既定4 cm）を取る。** 入らなければ数を減らす（詰めない）。転輪どうしや端の輪と重なっていたのが最初の指摘でした。`layout_overlaps` が空であることを確かめる。
- **上部転輪** は上側の走行面の下、端の輪から離して置く。
- **経路** は履板の中心線。凸の閉じた折れ線で、前下 → 前を上る → 上を後ろへ → 後ろを下る、の順（tudursvehiclemod の履帯の書式）。履板の間隔は経路長を割り切る値（`link_spacing`）。
- **輪には面に印を付ける。** 単色の円柱は回っても見えない。回転は経路1単位あたり 1/(2πr) 回転。
- **輪を浮かせない。** 転輪には軸とフレームまでのブラケット、誘導輪・起動輪にはヨークを付ける。Detail Pack を `attach.groups` で調べると、転輪・上部転輪・誘導輪の印などが、履帯のある機体ごとに14〜26個浮いていた（フレームの下端が転輪の上で止まっていた）。`crawler` は軸とブラケットを付ける。
- **拡幅するクローラーは、履板も輪もすべて動くフレームに載せる。** 本体（エンジン）が固定位置に描く履帯は、フレームが横へ動くと置いていかれる。`crawler(..., frame_part=動くフレーム, links="each")` で履板を1枚ずつ別パーツにし、動かす側（アドオン）が経路に沿って回す。
- 本体が履板1枚を並べて描く場合でも、プレビューと接触の確認は `links="laid"` で経路に並べて行う。

### 9.4 油圧シリンダー

- **両端のピンから外れないことが最優先。** 筒は相手側の取付点を向く（`aim`）、ロッドは取付点間の距離の伸びの分だけ伸びる（`reach`）関節にする（`ram_joints`）。チャンネル値に係数を掛けて長さを近似すると、起伏の途中でロッドが取付点からずれる（指摘を受けた「起伏中のずれ」）。`ram_drift` が0であることを確かめる。
- **段数は取付位置で決まる。** 最短 lmin と最長 lmax が `lmax ≤ 1.75 × lmin` なら、筒とロッドの2段で済む（`ram_stages` の simple）。
- **多段の伸縮シリンダーは、ブームやリーダーには使わない。** 大型杭打機のバックステーが「釣り竿」のような19段になり、非現実的と指摘された。段数が増えたら形で隠さず、取付位置を動かす。ダンプの荷台の多段ホイストは例外。
- **てこを確かめる。** ヒンジの近くを通るシリンダーは長さがほとんど変わらず、部品を持ち上げられない（探索で最初に見つかった「長さ一定の支柱」がこれ）。`ram_leverage`（ヒンジからシリンダーの線までの最短距離）を、ヒンジ〜取付点の1/10程度以上にする。
- **取付位置は探索で決める。** 親側の候補（甲板・ブラケット）と子側の候補（背面の高さ）を並べ、`ram_mount_search(..., max_stages=2, min_arm=...)` で、2段で済みてこが最大の組を選ぶ。手で置いた位置から始めない。
- **本数と太さは機体の格で決める。** 小型の杭打機は太いシリンダーを中央に1本（細い2本は弱く見える、と指摘された）、大型は左右2本の2段。シリンダーの根元は運転席や機関の覆いと干渉しない位置（中央線上や運転席の後ろ）に置く。
- 格納姿勢（リーダーを倒した状態）で、シリンダーが倒れた部品の下に収まり、甲板を突き抜けないことも見る。

### 9.5 アウトリガー・旋回体まわり

- **アウトリガーは旋回体の下の四隅に付け、斜めに張り出す。** 足回り（履帯）に付けると、旋回したとき作業装置に対して支えの位置がずれる。`outriggers(..., parent=旋回体)`。
- **張り出してから接地する。** 1つのチャンネルの前半で梁が出て、後半で脚が下りるように、`factor` と `min` / `max` で区切る。同時に動くと、脚の当て板が履帯に当たる。
- 張り出し長さは、履帯（拡幅後の幅）の外まで当て板が出る長さにする。
- 旋回体の下面と台車の間は旋回ベアリング（円柱）でつなぎ、浮かせない。

### 9.6 杭打機・リーダー

- **三点支持** は、リーダー下端のピンと、高さの半分ほどの背面に付けたバックステー（シリンダー）で支える形。格納時はリーダーを後ろへ倒し、旋回体の後部のレストに載せる（レストの高さは倒す角度から計算する）。
- **杭の通り道に箱を置かない。** リーダー下端に振れ止めのつもりで置いた四角い箱が、杭・キャップ・オーガと重なっていた。振れ止めは中央が空洞の半割リングで、杭を左右から抱え、左右に開く（`clamp_jaws`）。キャップやオーガ（ドライブロッド・ヤットコの下端）が近づいたら開くよう、チャンネルで動かす。蝶番の耳は親（リーダー）の面まで届かせる（4 cm 届かず浮いていた）。
- 簡略モデルでは、動きのない振れ止めを無理に付けず省略してよい。打撃式はハンマーが毎回地面近くまで下りるので付けない。
- **見た目とゲームの材料をそろえる。** 鋼管杭のモデルなら設置されるブロックは鉄、コンクリート杭ならコンクリート。モデルと設定（`pile_block`）を同じスクリプトから出すと食い違わない（原木が設置されていた指摘）。
- **ドライブロッドとヤットコの違いは関節で表す。** ドライブロッドは常に見えている同じ部品が持ち替えて下がる（`slide`）。ヤットコはヘッドの下に新しく現れる部品（ヘッド側を中心に `scale`、最小0.02で隠す）。
- 杭の軸は `scale`（長さ）、先端は `slide`（軸の長さに合わせて下がる）、回転は `spin` の親子に分けると、杭長を変えても先端の羽根が伸びない。

### 9.7 姿勢の検査

- **静止姿勢だけを見ない。** `sweep_poses({チャンネル: (下限, 上限)}, base=...)` は、各チャンネルを 0 / 0.25 / 0.5 / 0.75 / 1 にした姿勢と、全チャンネルを同時に動かした姿勢を返す。これを `sweep_check` と `ram_drift` にかける。
- `sweep_check(model, joints, poses, pairs=[(A, B)], skip=(...))`：
  - 浮き部品：`attach.groups` のまとまりが1つになること。履板（エンジンが描く）や吊った杭のように、離れていて正しい物は `skip` に入れる。
  - めり込み：当たってはいけない組（アウトリガーの当て板と履帯、振れ止めと回転ヘッド、倒したリーダーと運転席など）を `pairs` に入れる。両方の部品に姿勢を付けて調べる（`posed`）。
- この検査で実際に見つかったもの：転輪の重なり、起伏途中のシリンダーのずれ、張り出し前に下りる脚、杭の通り道の箱、振れ止めの耳の隙間、軸のない転輪。
- 見た目の確認は、側面の正投影（履帯の配置）と、起立・途中・格納の3姿勢（`pose_transforms`）。

### 9.8 実在機の扱い

- 実在の機種は**寸法と構造の比較にだけ**使う（クラスの公表値：機体重量、リーダー長、履帯幅、杭径など）。特定の機種の形・ロゴ・社名・型番を再現しない。オリジナルの意匠で、構造として成り立つ形にする。
- 比較に使った値は、モジュールの説明文（docstring）に「クラスの一般的な範囲」として書き残す（Detail Pack の各ファイルの冒頭）。
